What to send a scan-to-BIM provider

Inferred: a provider brief records the requested work and the decisions that remain open. The template below supports a scope discussion.

Prior: the input-file checklist covers scan packaging, registration and coordinates. This page covers the buyer's proposed work agreement.

Scope: what belongs in the proposal?

Verified (fetched vendor page): United-BIM lists discipline scope, building type, floor area, floor count, turnaround and deliverables as pricing factors. It describes a custom proposal after scope review. Vendor scope and pricing process.

Inferred brief fields: project purpose; included floors and zones; element categories; exclusions; available scan coverage; required date; and intended model use. Existing drawings can carry their date and revision status.

Inferred example: architectural walls and slabs for an internal layout review, with concealed services excluded. This example defines proposed work only.

LOD: which elements need which information?

Verified (fetched vendor page): United-BIM includes Level of Development in its pricing factors. Vendor LOD scope factor.

Inferred brief fields: an element schedule can record the requested LOD reference and edition, geometry, information fields, exclusions and acceptance method. Unresolved entries can remain open for agreement.

Inferred: a single LOD number does not establish measured accuracy for this sample. Independent checks and proposed tolerances need separate scope entries.

unknown: occlusion or opening not independently supported

Inferred: the brief can identify unsupported openings and hidden surfaces as unknown. Any proposed assumption needs a visible exception record.

Deliverable formats: what will the buyer receive?

Verified (fetched vendor page): United-BIM describes Revit (.rvt) and CAD (.dwg) outputs from scan data. These are attributed vendor offerings. Vendor scan-to-BIM outputs.

Inferred brief fields: required format, software version, model split, naming, coordinate frame and supporting QA report. For an IFC request, the brief can name the schema and exchange requirements. A native RVT requirement needs its own entry.

Prior: the free scan-to-BIM sample page provides the existing IFC sample and limitations. It establishes no native Revit delivery capability or client-ready accuracy.

File transfer: what needs agreement before upload?

Inferred transfer terms: sender and receiver; approved private destination; access permissions; expiry; retention; file inventory; total size; and a checksum manifest. The receiver's supported formats and upload limits remain confirmation items.

Inferred receipt record: package name, revision, receipt date, missing files and successful opening of the transferred copy. A failed receipt check can remain an open scope dependency.

Prior (site workflow): the existing request route creates a public GitHub Issue. Inferred privacy guidance: a public scope summary can omit private scans, access links and credentials. Private transfer requires a separately agreed route.
