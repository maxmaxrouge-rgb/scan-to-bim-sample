How can a buyer check a scan-to-BIM model before paying?

Inferred buyer intent: review the delivered model against agreed acceptance criteria before approving payment. Search demand remains unverified.

Inferred review guidance: this checklist proposes acceptance checks. The contract defines payment terms and required evidence.

Element coverage against scope

Inferred check: compare an element schedule with the agreed floors, zones and categories. Record missing elements and exclusions. Separate captured surfaces from inferred geometry.

LOD per category

Inferred check: compare each category with its agreed geometry and information requirements. A wall may meet its scope while an opening remains unsupported. A single LOD label cannot establish measured accuracy.

Prior: the LOD scope guide describes category questions.

Deviation spot checks against the point cloud

Inferred check: use the agreed coordinate frame and units. Select checks across floors, categories and difficult areas. Compare model surfaces with the registered cloud. Record point selection, distances, exclusions and the agreed tolerance. Retain screenshots and numerical results.

Inferred limitation: cloud agreement does not establish independent survey accuracy. Registration, hidden surfaces and sampling can affect the comparison.

IFC validity

Verified (fetched documentation): IfcOpenShell provides IFC validation and a JSON logger. Its validate function offers an express_rules option. Source: IfcOpenShell validation API.

Inferred check: retain the schema, validator version, options and findings. Test the file in the intended receiving software. Schema checks do not certify dimensional accuracy or contract compliance.

Naming and levels

Inferred check: compare element names, storey assignments and elevations with the scope schedule. Check units and the origin. Resolve duplicate or unclear names. Record any level that is provisional.
